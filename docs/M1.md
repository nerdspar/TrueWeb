# M1 — Client layer + CLI harness

The authenticated WebSocket client (`src/lib/server/truenas/`) and a CLI harness
(`scripts/cli.ts`). No UI. This is the layer everything else depends on.

## What's here

- `client.ts` — one long-lived JSON-RPC/WebSocket session to
  `wss://<host>/api/current`: auth, reconnect with backoff, subscription
  management, and job correlation. Every outgoing call passes the §6 allowlist
  (`send` is the single choke point).
- `allowlist.ts` — the §6 method map (tiers + job flags) and the never-expose
  denylist. Anything not listed is refused before it reaches the socket.
- `jobs.ts` — `JobRegistry`: correlates the job id a call returns with the
  `core.get_jobs` event stream, including the event-before-id race.
- `methods.ts` — typed wrappers for the methods whose signatures are verified
  against `https://api.truenas.com/v25.10/`.
- `env.ts`, `log.ts`, `protocol.ts` — config, a redacting logger, JSON-RPC types.

## Setup

Create a dedicated TrueNAS user and a **user-linked API key** for it (not a
`FULL_ADMIN` key — see `rbac.html`). For M1 the account needs, at minimum:

- authentication (`auth.login_ex`, `auth.me`),
- app reads + job/subscription access (`app.query`, `core.get_jobs`,
  `core.subscribe`),
- **`APPS_WRITE`** — verified as the role `app.start` / `app.stop` /
  `app.redeploy` require.

Then:

```bash
cp .env.example .env      # fill in TRUENAS_HOST, TRUENAS_API_KEY,
                          # TRUENAS_API_KEY_USERNAME; TRUENAS_VERIFY_TLS=false
npm install
```

Run the harness with the env file loaded:

```bash
node --env-file=.env --import tsx scripts/cli.ts <command>
```

(`npm run cli -- <command>` also works if the vars are already exported.)

## Acceptance checks (run against the box)

```bash
node --env-file=.env --import tsx scripts/cli.ts me           # prints auth.me
node --env-file=.env --import tsx scripts/cli.ts apps         # apps + state
node --env-file=.env --import tsx scripts/cli.ts stop <app>   # live job progress
node --env-file=.env --import tsx scripts/cli.ts start <app>  # live job progress
node --env-file=.env --import tsx scripts/cli.ts watch-apps   # state streams in
```

**Reconnect test:** run `watch-apps`, then drop the network (toggle Wi-Fi, or
pull the route to the NAS). The client logs `reconnecting in …ms`; restore the
network and it re-authenticates and re-subscribes on its own — no restart, no
input. Change an app's state during the outage and confirm the change appears
once it reconnects.

## Troubleshooting

**`SSL alert number 112` / `tlsv1 unrecognized name`, or `socket hang up`, on
connect.** You are hitting a reverse proxy, not TrueNAS. If Nginx Proxy Manager
owns `:443` on the box, that vhost matches on SNI/Host and rejects a bare-IP
connection (alert 112 with no SNI; `socket hang up` when SNI and Host disagree).
Per §10, connect to TrueNAS **directly** instead — its own UI listens on `444`
(HTTPS): set `TRUENAS_HOST=10.0.1.14:444` and `TRUENAS_VERIFY_TLS=false`, and
leave `TRUENAS_TLS_SERVERNAME` unset (a bare IP sends no SNI, which is what the
box's nginx expects). Only if you must route through the proxy would you use the
hostname on `:443` and set `TRUENAS_TLS_SERVERNAME`.
